## 답변

브라우저가 페이지를 렌더링 하는 과정은 크게

1. HTML 파싱
2. CSS 파싱
3. Render Tree 생성
4. Layout
5. Paint
6. Composite

순서로 진행됩니다.

### 1. HTML 파싱

먼저 브라우저는 서버로부터 받은 HTML 문서를 위에서 아래로 파싱하면서 **DOM Tree**를 생성합니다.
DOM은 HTML 태그들을 브라우저가 이해할 수 있는 개체 구조로 표현한 것으로, HTML 파싱은 tokenization과 트리 구조를 포함합니다.

### 2. CSS 파싱

동시에 HTML 안에서 CSS 파일을 만나면 CSS를 다운로드하고 파싱해서 CSSOM Tree를 생성합니다.
CSSOM은 각 요소에 어떤 스타일이 적용되는지를 나타내는 구조입니다.

### 3. Render Tree 생성

DOM과 CSSOM을 결합해서 Render Tree를 만듭니다. Render Tree에는 실제 화면에 표시될 요소만 포함됩니다(display: none 제외).

### 4. Layout

Render Tree가 만들어지면 브라우저는 각 요소의 크기와 위치를 계산하는 Layout, 또는 Reflow 과정을 수행합니다.
이 단계에서 요소가 화면의 어디에, 얼마나 크게 배치될지가 결정됩니다.

### 5. Paint

이후 브라우저는 계산된 위치와 스타일을 바탕으로 픽셀을 채우는 Paint 과정을 수행합니다.
이때 색상, 배경, 테두리, 텍스트, 그림자 등이 그려집니다.

### 6. Composite

마지막으로 여러 레이어를 합쳐 최종 화면을 만드는 Composite 과정이 진행됩니다.
transform, opacity 같은 속성은 별도 레이어에서 처리될 수 있어 Layout이나 Paint를 다시하지 않고도 비교적 빠르게 화면 갱신이 가능합니다.

### 알아두기

JavaScript는 이 과정에 영향을 줄 수 있습니다. HTML 파싱 중 `<script>`를 만나면 기본적으로 HTML 파싱이 중단되고 JS가 실행됩니다. JS는 DOM이나 CSSOM을 변경할 수 있기 때문입니다. 따라서 JS 파일이 크거나 실행 시간이 길면 렌더링이 지연될 수 있습니다.

그래서 프론트엔드에서는 렌더링 성능을 개선하기 위해 CSS와 JS 번들 크기를 줄이고, 불필요한 reflow와 repaint를 줄이며, 이미지 최적화, lazy loading, code splitting 등을 적용합니다.
