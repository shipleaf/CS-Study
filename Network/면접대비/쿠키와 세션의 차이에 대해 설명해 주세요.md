## 답변

쿠키는 브라우저에 저장되는 정보로, 서버에서 생성되어 브라우저에 저장되며, 각 요청마다 쿠키를 자동으로 포함하여 요청할 수 있다.
세션은 서버가 사용자 정보를 관리하기 위한 저장 공간 또는 연결 개념, 사용자의 인증 정보 등을 서버의 메모리, Redis, DB 등에 저장 및 관리하는 방식이다.

## 꼬리질문

### 세션 방식의 로그인 과정에 대해 설명해 주세요.

세션 방식으로 로그인에 성공하면 서버에서 현재 로그인한 사용자 정보를 포함하는 세션을 생성합니다.
생성 후 해당 세션을 식별할 수 있는 세션ID를 쿠키에 저장하여 사용자에게 보냅니다.
사용자는 이후 요청마다 쿠키에 저장된 세션 ID를 함께 전송하고, 서버는 이를 통해 세션 저장소에서 사용자 정보를 조회하여 인증을 수행합니다.

### HTTP의 특성인 Stateless에 대해 설명해 주세요.

HTTP 프로토콜은 효율적인 응답-요청 구조를 위해 몇가지 특성을 가지는데, 그 중 하나가 Stateless입니다.
Stateless는 서로 다른 요청끼리의 정보 공유를 하지 않는다는 특성입니다.
예를 들어, 사용자가 로그인을 수행한 요청 1, 그 이후의 요청 2가 있을 때, 요청 2는 사용자가 로그인 상태인지를 확인할 수 없습니다.
이를 보완하기 위해(사용자 정보를 기억하기 위해), 나온 기술이 쿠키와 세션 기술인 것입니다.

#### HTTP의 특성

1. 요청-응답 기반 프로토콜
2. 미디어 독립적 프로토콜: 가능한 자원을 특정하지 않으며, 단지 자원과 상호 작용하는 데 사용할 수 있는 인터페이스(수단 역할)를 정의할 뿐입니다.
3. 스테이트리스 프로토콜: 서로 다른 요청과 관련된 클라이언트의 상태를 기억하지 않는다. 장점이 명확, 모든 요청에 대한 정보를 저장하는 게 서버에는 큰 부담.
   서버를 여러 대로 구성할 때도 장점을 가진다.
   확장성과 견고성
4. 지속 연결성

### Stateless의 의미를 살펴보면, 세션은 적절하지 않은 인증 방법 아닌가요?

맞다. HTTP의 설계 원칙인 확장성과 견고성에 위배될 수 있다. 이를 보완하기 위해 토큰 방식이 등장했다.
